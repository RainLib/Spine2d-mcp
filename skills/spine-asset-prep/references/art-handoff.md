# 图层到 Spine 的交接

交接记录描述实际素材，不要求任何游戏采用固定角色结构。可复用已有 manifest；没有时创建一份 JSON，记录下面这些会影响导入的字段。它是交接约定，不是本 MCP 已实现的自动导入 schema。

| 信息 | 用途 |
| --- | --- |
| 原图相对路径、SHA-256、生成提示词／来源 | 区分原始内容、修订版本和导出纹理 |
| 可编辑工程路径、应用／接口与导出版本 | 后续继续调整并重现导出 |
| 画布尺寸、坐标方向、Spine 原点与单位缩放 | 防止画布像素直接当作骨骼局部坐标 |
| 每层稳定名称、导出路径、裁切矩形、画布锚点 | 裁切后仍可还原素材位置 |
| 需要的 skin、slot、attachment key 和前后关系 | 避免文件名、占位名和实际附件名混用 |
| 状态组合、默认可见性与互斥关系 | 保持嘴部／道具状态及默认姿态正确 |
| 图片尺寸、导出哈希及预览路径 | 绑定校验报告，避免检验了旧纹理 |

通常图像坐标向右／向下，骨架坐标向右／向上。若项目采用简单的原点与缩放映射，应记录并验证：`spine_x=(canvas_x-origin_x)*scale`、`spine_y=(origin_y-canvas_y)*scale`。有旋转、非均匀缩放或已栅格化变换时，记录实际变换，不能继续套用这个简式。

裁切图中的点先加上裁切偏移还原到画布，再映射至骨架。骨骼局部绑定坐标还需由骨骼的世界变换反算；图层锚点不自动等于 Spine 骨骼局部坐标。

图层面板的上层通常画在前面，Spine 导出 slot 数组按自身格式表达绘制顺序；根据实际导入预览核对，不直接复制面板索引。组、遮罩和混合模式可能无法在游戏中等价表示，需将必要效果烘入派生纹理，保留可编辑母版与差异说明。

整体验收比较合成形象及各个需要的状态：前后遮挡、嘴部对齐、透明边缘、道具握点、脚底基准和裁切位置。原始像素没变不代表导出对齐正确；画面看起来一致也不代表分层文件仍可编辑。

若使用官方 Photoshop-to-Spine 脚本或其他导出器，先按该版本文档确认命名标签与坐标规则，不臆造 `[slot]` 等语法。通用包的 `stage_asset_bundle` 消费已经存在的 Spine JSON 及图片；它不会把 PSD／`.pcraft` 自动转换为完整骨架。
